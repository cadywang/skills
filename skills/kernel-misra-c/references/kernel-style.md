# Linux 内核 coding style 要点

## 权威来源

优先检查目标内核树中的：

- `Documentation/process/coding-style.rst`
- `scripts/checkpatch.pl`
- 对应子系统的 `Documentation/` 和维护者说明

不同内核版本和子系统的要求可能不同，本文只是施工检查表。

## 格式

- 缩进使用 8 字符 tab。
- 尽量不超过 80 列；长字符串、日志和宏按所在文件惯例处理。
- 函数左花括号独占一行；`if`、`for`、`while`、`switch` 使用 K&R 花括号风格。
- 二元运算符两侧留空格；一元运算符后不留空格。
- 指针声明写成 `char *p`，星号贴近变量名。
- 行尾不留空白；文件使用 LF。
- 不在同一行写多条语句；不要用逗号声明多个不同类型的变量。
- 单语句控制流通常省略花括号，但 MISRA 适用时以 MISRA 为准。

## 命名

- 函数、变量和文件名使用 snake_case。
- 名称表达用途，避免 `data`、`tmp`、`flag` 这类脱离上下文后无意义的名称。
- 宏和常量使用大写；宏参数和整个表达式加括号。
- 尽量不用 typedef 隐藏结构体或指针类型；使用项目已有的固定宽度类型和子系统类型。
- 文件内符号加 `static`，避免污染全局命名空间。
- 导出符号遵循子系统的命名前缀和 namespace 约定。

## 函数与声明

- 一个函数只承担一个清晰职责；复杂逻辑拆成有名字的辅助函数。
- 遵循目标文件的声明位置；旧 C 标准项目不要在语句后随意混入声明。
- 能在头文件用 `static inline` 表达的小函数，不要写成复杂宏。
- 参数和返回值语义写清楚；成功、失败和部分完成分别如何表示。
- 修改接口时同步检查调用方、文档和测试。

## 错误处理

- 内核接口通常返回负 errno，例如 `-EINVAL`、`-ENOMEM`、`-EIO`。
- 指针错误使用项目规定的 `ERR_PTR()`、`IS_ERR()`、`PTR_ERR()` 约定。
- 所有可能失败的分配、映射、复制和硬件访问都要检查返回值。
- 清理顺序与申请顺序相反；避免错误路径漏解锁、漏释放或漏关闭。
- 内核清理标签 `goto` 很常见，但可能与 MISRA 冲突；见 `conflicts.md`。
- `BUG()`、`BUG_ON()` 只用于项目认可的不可能状态；安全关键代码优先恢复、告警或返回错误。

## 内存与并发

- 分配器、GFP 标志和释放函数必须配套；错误路径也要释放。
- `copy_from_user()`、`copy_to_user()` 返回未复制字节数，不能只判断“非零/零”而忽略语义。
- spinlock 临界区不能睡眠；mutex 可以睡眠；中断上下文使用项目允许的锁。
- 共享数据要明确由锁、原子操作、RCU 还是单线程上下文保护。
- `volatile` 只描述对象可能被外部改变，不提供原子性、互斥或内存排序。
- MMIO 使用子系统提供的 read/write accessor；不要把普通变量声明成 `volatile` 代替屏障。
- 熟悉并使用 `ARRAY_SIZE()`、`container_of()`、`min()`、`max()` 等内核辅助宏，但注意参数求值次数。

## 注释与文档

- 注释解释为什么这样做、约束是什么、锁如何持有、错误如何传播。
- 不重复代码表面行为，不写与代码不同步的历史故事。
- 内核代码优先使用 `/* ... */`；不要使用 `//`，除非目标文件明确允许。
- 导出函数和复杂接口使用 kernel-doc 风格。
- 临时绕过必须写清楚缺陷、风险、移除条件和责任人。

## 宏

- 宏名大写，参数和整体表达式加括号。
- 多语句宏使用 `do { ... } while (0)`。
- 避免参数重复求值；能使用 `static inline` 时优先使用。
- 不要在宏里隐藏 `return`、`goto`、锁获取或资源分配。
- 宏参数类型和副作用要在注释或命名中体现。

## 检查命令

按项目实际路径运行：

```bash
scripts/checkpatch.pl --no-tree --strict -f path/to/file.c
scripts/checkpatch.pl --git path/to/patch
```

可用的补充检查：

```bash
make W=1
make C=1 CHECK=sparse
smatch --project=...
```

`checkpatch.pl` 只检查风格和部分常见问题，不证明逻辑正确、并发安全或 MISRA 合规。

## 提交前检查

- 缩进、列宽、花括号、空行和尾随空白。
- 命名、`static`、头文件依赖和导出符号。
- 每个错误路径都释放资源并返回正确错误码。
- 共享数据的保护方式明确。
- 宏没有重复求值和隐藏控制流。
- 新增或修改行为有对应测试或可复现验证。
- 偏差和未验证项已记录。
